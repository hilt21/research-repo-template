# Research Repository Template

让研究可以继续，让判断有据可查。

这是供 Codex 使用的单课题研究仓库模板。你可以自然地说“研究这个问题”“继续上次研究”“把这轮整理下来”。Agent 管理文件和研究过程；你集中审阅值得保留的知识变化。

## 开始使用

1. 在 GitHub 使用此 Template 创建自己的仓库，克隆到本地并在 Codex 中打开。
2. 准备 Git、Codex 和 [uv](https://docs.astral.sh/uv/getting-started/installation/)。在仓库执行一次 `uv sync`。
3. 告诉 Codex 你想研究的课题。Agent 会读取 AGENTS.md，确认问题、范围与完成标准，并初始化课题。

根目录初始没有研究知识。可以先说：“请查看 `examples/emb` 的研究记录，告诉我目前知道什么、还缺什么证据。” 示例状态与实际验收结果见 [验收记录](docs/acceptance.md)。

## 日常使用

| 你说 | 仓库里会发生什么 |
| --- | --- |
| 帮我研究这个问题 | Agent 阅读已有知识、查资料并保存研究进度 |
| 继续上次研究 | 恢复问题、已知、待验证事项和下一步 |
| 把这轮整理下来 | 形成候选判断、运行检查、展示一份审阅摘要 |
| 我确认接受这些变化 | 提交刚才审阅的知识及关联研究进度 |
| 根据目前研究写份报告 | 形成引用关键判断的报告、表格或示意图 |

“进度已保存”表示文件留在本地；“知识已入库”表示你已确认且 Git 提交成功。假设也可以入库，它仍是假设。新会话可从原工作副本恢复未提交进度，跨设备需先提交并同步；本地全文缓存不会自动同步。

## 文件在哪里

- `knowledge/`：课题、来源记录、判断和按需创建的对象，采用 OKF v0.2。
- `traces/`、`tasks/`：可继续的研究过程。
- `artifacts/`：报告等输出，关键判断可追溯到 Claim。
- `.agents/skills/`：四个 Agent 行为协议；`scripts/`：确定性操作。
- `examples/emb/`：隔离的真实研究示例；`tests/`：合成行为测试，不能当作证据。

需要维护协议时再看 [工作流与命令](docs/workflow.md)、[字段契约](schemas/objects.yaml)、[完整规格](docs/repository-spec-v0.1.md) 和 [领域术语](CONTEXT.md)。

首版按私有模板使用，主要实测 Codex；没有常驻服务或数据库。公开发布及开源许可另行决定。
