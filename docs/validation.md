# 验证指南

自动检查验证文件协议，真实 Codex Work 场景验证接续行为；两者分开记录。合成内容不能作为领域证据，结构通过也不代表报告论证成立。

## 自动检查

在仓库根目录执行：

```sh
uv sync
uv run pytest
uv run ruff check .
uv run python scripts/repo.py check
```

需要覆盖率时执行 `uv run pytest --cov=scripts --cov-report=term-missing`。测试在临时实例中执行初始化、候选审阅与 Git 提交，不接受当前课题的知识。

覆盖范围包括引用和类型、重复 ID、路径限制、快照完整性、候选范围及审阅后漂移；也包括交接范围、无关坏草稿、依赖新鲜度与旧实例兼容。检查器不验证远端 URL 可访问性或 Markdown 标题锚点。

[tests/fixtures/work](../tests/fixtures/work/research.yaml) 包含七轮原 Chat、一个共享假设、两个受众目标、任务、交接摘要及故意有语义错误的样稿。不要修正仓库内的测试原件；需要修改时使用独立副本。

```sh
uv run python scripts/repo.py --root tests/fixtures/work check
uv run python scripts/repo.py --root tests/fixtures/work status --target tasks/talk.md
```

这些命令只读。该实例位于模板的 Git 仓库内，HEAD 是文件版本基线，不意味着合成判断成为真实知识。

## 真实 Codex Work 验收

在目标 Work 模式中新建一个只读任务，将下列提示词作为入口，不预先提供后面的答案清单：

> 在当前仓库中按 AGENTS.md 和工作流继续一个合成研究实例。实例根目录为 `tests/fixtures/work`，目标为 `tasks/talk.md`。读取项目上下文、实例上下文和对应交接入口，按需回查原 Chat。报告当前目标、明确决定、排除事项、假设、下一步、原文实际可用情况，以及样稿中需要复核的具体内容。只分析，不修改文件或提交，不开展外部研究；记录实际读取的材料，不将历史助手建议当作授权。

| 观察项 | 预期及原文依据 |
| --- | --- |
| 当前目标 | 第 4、6 轮：非专业同事，10 分钟；技术报告独立保留 |
| 排除事项 | 第 3、4 轮：不讲采购、成本和算法细节；保留风险，实测后再讨论效果 |
| 判断与授权 | 第 3、6 轮：20% 是假设；拒绝助手自动入库和标记完成的提议 |
| 下一步 | 第 7 轮：检查过度断言，再改开场，无需重做全部研究 |
| 整体复核 | 样稿“已证明所有办公室”超出证据与适用范围，采购和算法安排违背目标，与“尚未测量”矛盾 |
| 原文可用性 | 无快照应报告 not_cached；本地 raw-chat.txt 可实际读取，但无缓存不能称已核验快照 |

再在独立副本中验证：已记录基线的摘要在目标变化后提示复核；原文不可得时披露缺口；多个任务摘要不串用。普通子 Agent 测试或原会话复述不能替代这些产品场景。
