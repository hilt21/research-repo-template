# 维护知识与输出

确定实例并读取 [工具工作流](../../../docs/workflow.md)。先运行 status 与 check，明确当前知识基线、候选变化及问题范围。

- 优先维护本次研究涉及的条目；用户要求全库检查时再扩大范围。
- 结构错误由脚本定位，Agent 可在目标唯一明确时修复，随后重新检查；不通过编造来源或改 Schema 绕过错误。
- 新证据挑战旧判断时检查适用条件，保留双方证据，提出 contested 或范围修订。
- 用 impact 遍历显式 Claim 依赖。报告如何改写由 Agent 判断；完成复核才置 current，未完成保持 needs_review。
- 使用 index 重建索引；索引不承载新判断。
- 需要持续跟踪的实质研究问题可建立 Task，不为每条普通维护提示自动制造用户待办。
- 保存本轮 Trace，知识修订与关联报告变化交给本仓库 commit-knowledge 流程集中审阅，不自动提交。
