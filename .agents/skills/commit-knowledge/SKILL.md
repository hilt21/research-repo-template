# 集中审阅与知识入库

读取实例 AGENTS.md 和 [工具工作流](../../../docs/workflow.md)。先确定本轮 Trace、相关来源、候选知识与任务，运行 status 识别基线。

1. 根据研究内容组织关键 Claim 及必要对象。保留假设、争议和适用条件；用户允许保留不代表 verified。
2. 对改变的 Claim 调用 impact 找出相关报告，完成需要的复核或保留 needs_review。
3. 在对应 Trace 的“本轮知识变化”写语义摘要：前后变化、依据、争议、输出影响和下一步。关联来源及任务应包含在本轮范围。
4. 运行 index 和 check。Agent 可以修复结构，但必须重新执行检查；不能修改规则来消除本应阻断的错误。
5. prepare 逐个列出本轮文件。将语义摘要、实际提交范围和提示展示给用户，取得对具体变化的确认。
6. 仅在确认后使用返回 ticket 执行 accept --confirmed。若摘要或实质内容变化，重新准备和审阅；不得直接 git commit 研究文件。
7. 根据实际结果报告入库成功及 commit，或说明具体失败。相关 Trace 随提交保存，其暂定内容仍为过程记录。

本轮涉及交付时，按工作流纳入 brief、相关任务/输出和交接所需引用，检查依赖变化；无需创建第二套接受流程。用户接受交付不等于接受新 Claim，交接内容也不能扩展执行授权。

本 Skill 可自然触发，但触发本身不代表用户已经审阅并接受了尚未展示的判断。模板建设的授权同样不能代替真实课题知识的审阅。
