# 开展或继续研究

确定实例根目录，读取 research.yaml、AGENTS.md 与 [工具工作流](../../../docs/workflow.md)。本仓库示例始终与根课题隔离。

- 未初始化时收敛问题、范围、完成标准，用 init 初始化；不要自行选另一个课题。
- 恢复先运行 status，读取 Topic、索引、相关 Task、最近 Trace。区分 HEAD 中的知识与工作区候选变化。
- 给用户简短的当前问题、已知、关键不确定性与下一步，再开展研究。
- 用 new 生成所需对象和 ID。短研究只保存 Trace；需要跨会话推进、有待办或阻塞时创建 Task。
- 阅读实际来源再作判断，记录获取时间与具体定位。用 snapshot 保存取得的原文，默认留在本地缓存。
- 关键阅读或阶段发现后保存 Trace，记录可观察行动、证据取舍、缺口和下一步，无需复制全部聊天或内部思维。
- 关键判断可成为候选 Claim；普通关系用链接。假设标 hypothesis，反证先核对适用条件。
- 报告置于 artifacts，research.claims 记录依赖；新判断先作为草稿，不能因写进报告就声称已入库。
- 调用 check 检查结构。完成研究不代表已经提交；用户要求整理时按本仓库 commit-knowledge Skill 执行。

来源不可取得时记录限制，不能把摘要推测当作已读全文。所有技术判断的证据质量与适用条件由你判断，脚本只处理结构。
